# task-progress

交代一件事給 Claude 之後，輸入框上方即時顯示做到幾 %。Claude 開工前先預估這件事要呼叫幾次工具、花多少錢，插件數著實際的工具次數與花費，兩個比例平均就是進度。每做完一件，預估和實際都記下來，下一次的預估照過去的偏差自動校正。

## 怎麼看

- **輸入框上方的卡片**：只佔一行，左邊一條細長條，右邊是「◓ 35% · 工具 2/10 · $1.00/$2.00 · 0:20 · 約剩 0:37 · Bash · 跑全部的測試」。點文字就打開側邊面板。
  - 轉圈每秒換一格，經過時間每秒跳：Claude 在想、沒有新輸出的時候，也看得出它還在動。
  - Claude 還沒給預估（或這件事小到不用估）時顯示「進行中」，長條是一小段每秒往右走，不顯示百分比。
  - 做完之前最多 99%；實際超過預估時顯示「超出預估 130%」，長條換成橘色。
  - 開始 5 秒、做到 5% 之後才推剩下的時間，照目前的速度線性推。
  - 做完留著「✓ 完成 · 工具 14/12 · $0.95/$0.80 · 2:31」直到下一件事；只是聊天、沒動過工具的不佔位。有問卷要用這一格時會讓開。
- **側邊面板**：這件事的說明、進度條、工具次數與花費各自的分子分母、Claude 原本估的數字與套了多少倍的校正、正在跑的工具、剛跑完的工具與各花幾秒、子 agent 呼叫了幾次工具，以及最近幾件事的「預估 → 實際」。
- **`/progress`**：打開側邊面板；面板放不下的地方，把狀態印在對話裡。

## 怎麼算

- **一件事**：你打一段話送出，到主對話那一輪結束。背景工作做完、引擎自己接著跑的那一輪（沒有打字）算回同一件事。
- **預估**：插件註冊一個工具 `estimate`，系統提示裡加一段固定說明，要 Claude 在要動用工具的事情開始前先呼叫它，給工具呼叫總次數與總花費（美元）。範圍明顯變了可以再呼叫一次修正。這個工具一開始就放在工具清單裡（不用先 ToolSearch 載入），也不問權限：它只記下幾個數字。
- **工具次數**：只算主對話自己的呼叫，派一個子 agent 算一次；子 agent 在裡面呼叫的另外列，不算進進度。`estimate` 本身不算。
- **花費**：Claude Code 自己記的 session 累計花費（就是 `/cost` 的數字），減掉開始時的值，所以含子 agent。每秒讀一次，每次模型請求結束才會變。宿主沒有花費帳時只看工具次數。
- **進度**：工具次數 ÷ 目標次數、花費 ÷ 目標花費，兩個平均。

## 校正

做完一件有預估的事記一筆：Claude 第一次估的、最後改成的、實際的工具次數、花費與時間。紀錄跨 session 留在插件的 store 裡，最多 100 筆。

下一件事 Claude 宣告預估時，拿最近 20 筆「做完」的紀錄，工具次數與花費各自算「實際 ÷ 第一次預估」的中位數，滿 3 筆就把 Claude 的數字乘上這個倍率當目標。倍率夾在 0.25 到 4 倍之間。

- 中斷、出錯的不拿來算：沒做完的實際數字不代表那件事的大小。
- Claude 中途改過預估，就直接用它改的數字、不再乘倍率：它改的時候已經看到實際做了多少。
- 倍率不告訴 Claude，系統提示那一段也固定不變。一來 prompt cache 不會因為紀錄變了而每輪失效；二來 Claude 自己跟著調的話，同一個偏差會被修正兩次。

## 已知的限制

- 預估是 Claude 的判斷，第一兩件事會不太準；校正要累積幾件事才有用。不同種類的事（查問題 vs. 大改）偏差可能不同，目前全部混在一起算一個倍率。
- 花費每次模型請求結束才更新，請求進行中百分比只靠工具次數動。
- 熱重載時錯過了一件事的開始，從 Claude 宣告預估那一刻開始算。
- 需要 Claude Code 2.1.288 以上（用到 `prompt.compose`）。比較舊的版本載入不了這個插件，cost-ledger 不受影響。
