# cost-ledger

把 Claude Code 的每一次模型請求逐筆記帳：用了哪四種 token、照 API 定價換算是多少錢、輸出速度多快、這段工作是為了哪支 PR。主對話和子 agent 都記。

金額是照 API 定價換算的等值金額，不是帳單。

## 怎麼看帳

- **輸入框上方的卡片**：只佔一行：「花費 $3.42 · 輸出 85 tok/s（平均 72）」，右邊跟一條細的各項金額比例長條（終端機寬度不夠就只留文字，不折行）。點文字就打開側邊面板。有問卷要用這一格時會讓開，這個 session 還沒有請求時不顯示。
- **側邊面板**：這個 session 的金額依 token 種類、來源（主對話或哪個子 agent）、模型、歸屬（PR 或分支）拆開，加上最近的請求與各自的速度。可以一鍵複製成 markdown 貼進 PR 內文。
- **`/ledger`**：打開側邊面板；面板放不下的地方，把表印在對話裡。
- **`/ledger pr <編號>`**：打開面板並切到那支 PR 的帳，跨所有 session 與子 agent。
- **模型可以呼叫的工具 `ledger`**：不給 `pr` 查這個 session，給 `pr` 查那支 PR，回傳 markdown。

## 記了什麼

每次請求一列，寫在 `~/.claude/cost-ledger/<日期>/<session id>.jsonl`（檔案長到 3.5 MB 換下一個 `-2`、`-3`）。

- **四種 token**：未快取的輸入、輸出、快取讀取、快取寫入，各自照單價換算。
- **快取寫入的時效**：引擎給的用量沒有分 5 分鐘和 1 小時，所以用推定的：主對話 1 小時、子 agent 5 分鐘。每一列都標著是推定的。
- **輸出速度**：輸出 token 除以生成時間；生成時間從收到第一個回應片段算到串流結束，等第一個片段的時間（排隊、讀 prompt）另外記、不算進速度。平均是總輸出除以總生成時間，所以長的回應權重大。
- **PR 證據**：`gh pr create` 輸出的 PR 網址、`gh pr checkout/diff/review/comment/edit/ready/merge <編號>`、`git push` 推到的分支、`git switch -c` 這類建分支的指令。`gh pr view` 常拿來讀別支 PR 當參考，不算。
- **子 agent**：派出時的任務說明、模型、指定的工作目錄。

### 歸屬怎麼算

同一個 session、同一個 agent 的請求依時間排，每次請求歸給它之後的第一個 PR 證據（做到開 PR 為止的工作算那支），最後一個證據之後的收尾歸最後那個。完全沒有證據的主對話，退回請求當下所在的分支。查某支 PR 時，歸給那個 PR 編號的、加上歸給那支 PR 分支的，都算。

## 已知的限制

- 思考 token 與網路搜尋次數插件拿不到，不在帳上。
- 快取寫入的時效是推定的，跟實際可能有差。
- 帳從插件載入之後才開始記；面板會一併列出 Claude Code 自己記的 session 累計，兩邊的差就是載入前的部分加上推定誤差。
- 請求中途重試的話，那次的生成時間會連重試前的等待一起算進去，速度偏低。
- 輸出 token 的數字要等回應結束才拿得到，所以速度是每次請求結束後更新，不是邊產生邊跳。

## 定價表

單價寫在 `hooks/register.tsx` 的 `PRICES`，`PRICE_TABLE` 是官方定價表的日期，每一列都記著當時用的單價。不在表裡的模型照記 token、不算金額，面板會列出有幾次。
